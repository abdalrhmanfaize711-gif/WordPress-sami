# دليل التشغيل والإعداد — رِحلات اليمن

هذا المشروع يحتوي على واجهة WordPress وإضافة PHP، ونظام Strapi مستقل لإدارة محتوى الوجهات. لا حاجة إلى تعديل PHP يدويًا. تحتاج إلى Docker Desktop لتشغيل النسخة المحلية. الموقع لا يحجز رحلات أو يضمن إمكانية السفر؛ أضف معلومات الحجوزات بنفسك فقط إذا جهزت لها خدمة مناسبة.

## أ. تشغيل الموقع على جهازك

### 1. تثبيت Docker Desktop

نزّل Docker Desktop وثبّته، ثم شغّله وانتظر حتى تظهر حالة أن Docker يعمل. لا يلزم تثبيت PHP أو Node.js يدويًا؛ الحاويات توفرهما للمشروع.

### 2. تنزيل المستودع وإعداد الأسرار المحلية

افتح PowerShell ونفّذ:

```powershell
git clone https://github.com/abdalrhmanfaize711-gif/WordPress-sami.git
cd WordPress-sami
Copy-Item .env.example .env
```

ملف `.env` خاص بجهازك ولا ترفعه إلى GitHub. القيم في `.env.example` للتطوير المحلي فقط. لا تستخدمها على خادم متاح للإنترنت؛ غيّر كلمات المرور والمفاتيح هناك إلى قيم طويلة عشوائية واحفظها كأسرار في منصة الاستضافة.

### 3. بدء الخدمات

في مجلد المشروع نفسه، نفّذ:

```powershell
docker compose up -d --build
```

قد يستغرق التشغيل الأول وقتًا لتنزيل WordPress وStrapi وقواعد البيانات وبناء لوحة Strapi. تحقق من الحالة:

```powershell
docker compose ps
```

إذا لم تبدأ Strapi، اعرض سجلها:

```powershell
docker compose logs -f strapi
```

العناوين المحلية:

- WordPress: [http://localhost:8080](http://localhost:8080)
- لوحة Strapi: [http://localhost:1337/admin](http://localhost:1337/admin)

### 4. إعداد WordPress لأول مرة

1. افتح `http://localhost:8080` واختر العربية.
2. أكمل معالج WordPress وأنشئ حساب مدير الموقع.
3. من **الإضافات ← الإضافات المنصّبة** فعّل **Yemen Travel — Yemen Tourism**. ملفاتها موجودة مسبقًا في المشروع.

### 5. إعداد Strapi لأول مرة

1. افتح `http://localhost:1337/admin` وأنشئ حساب مدير Strapi.
2. انتقل إلى **Settings → API Tokens → Create new API Token**.
3. أنشئ رمزًا باسم `WordPress tourism reader` واختر **Read-only**، ثم أنشئه وانسخه فورًا إلى مكان خاص. لا تنشره ولا تضعه في محتوى الصفحة.
4. ستجد نوعي المحتوى الجاهزين في **Content Manager**: **إعدادات الموقع السياحي** و**الوجهات السياحية**.

### 6. إدخال بيانات الموقع والوجهات

استخدم [data/demo-content.json](../data/demo-content.json) مرجعًا جاهزًا للقيم. من لوحة Strapi:

1. افتح **إعدادات الموقع السياحي** وأدخل اسم الموقع، والعنوان والوصف، ورابط صورة الواجهة واعتماد الصورة. احفظ ثم اضغط **Publish**.
2. افتح **الوجهات السياحية ← Create new entry**. أدخل الاسم والمنطقة والوصف ورابط الصورة واسم المصور وصفحة المصدر ورابط الترخيص ورابط اليونسكو ورقم الترتيب.
3. اضغط **Save** ثم **Publish** لكل وجهة. كرر ذلك لسقطرى وصنعاء القديمة وشبام وعدن من ملف البيانات التجريبية.
4. لا تحذف روابط المصدر والترخيص؛ تظهر اعتمادات الصور تحت الصور في الموقع.
5. أدخل رقم واتساب والبريد في إعدادات الموقع إذا أردت إظهار وسائل التواصل. اكتب رقم واتساب مع رمز الدولة، أرقام فقط، مثل `9677XXXXXXXX`.

الصور التجريبية مستضافة على Wikimedia Commons، لذلك يلزم اتصال إنترنت لعرضها. يمكن تغيير الصور من Strapi إلى صور تملك حق استخدامها، مع تحديث المصور والترخيص والمصدر.

### 7. ربط الإضافة بـ Strapi

في WordPress افتح **الإعدادات ← Yemen Travel**، ثم أدخل:

- **عنوان Strapi:** `http://strapi:1337` عند تشغيل المشروع عبر Docker Compose كما في هذا الدليل. هذا اسم الخدمة داخل الشبكة الخاصة للحاويات.
- **رمز القراءة:** رمز Read-only الذي أنشأته في Strapi.
- **رقم واتساب:** اختياري إذا لم تضعه في إعدادات Strapi.
- **التخزين المؤقت:** اكتب `0` أثناء التحقق كي تظهر كل التعديلات فورًا، ثم غيّره مثلًا إلى `300` بعد ذلك.

احفظ الإعدادات. يرسل WordPress طلبات Strapi من الخادم باستخدام رمز القراءة؛ الرمز لا يظهر في كود صفحة الزائر. يسمح إعداد التطوير المحلي بالاتصال الداخلي باسم `strapi` وعلى المنفذ `1337` فقط.

### 8. إنشاء الصفحة الرئيسية

1. من WordPress افتح **الصفحات ← أضف صفحة**، وسمّها **الرئيسية**.
2. أضف كتلة **Shortcode** وضع فيها:

   ```text
   [yemen_travel_home]
   ```

3. انشر الصفحة.
4. افتح **الإعدادات ← القراءة**، واختر عرض **صفحة ثابتة**، وحدد صفحة **الرئيسية**.
5. افتح `http://localhost:8080` في نافذة خاصة وتحقق من ظهور الوجهات والصور والروابط.

يمكن وضع `[yemen_destinations]` في صفحة أخرى لعرض بطاقات الوجهات فقط.

## ب. اختبار الربط

بعد نشر سجل واحد على الأقل في Strapi، تحقق من التالي:

- بطاقة الوجهة تظهر في الصفحة الرئيسية ومعها الاسم والوصف.
- صورة الوجهة تظهر، ورابط المصدر والترخيص يعملان.
- رابط اليونسكو يفتح في نافذة جديدة.
- رابط واتساب أو البريد لا يظهر إلا بعد إدخال وسيلة تواصل.
- افتح الصفحة بعد تغيير اسم وجهة؛ إذا كان التخزين المؤقت صفرًا يجب أن يظهر التغيير عند التحديث.

إذا ظهر تنبيه عدم وجود وجهات، تأكد من نشر السجلات (Publish)، وصحة رمز القراءة وعنوان Strapi. راجع السجلات بـ `docker compose logs -f wordpress` و`docker compose logs -f strapi`.

## ج. النشر على الإنترنت

Docker Compose المعدّ هنا للتطوير المحلي. قبل نشر الموقع:

1. اختر استضافة تدعم Docker أو استضف WordPress وStrapi على خدمتين متوافقتين، مع قواعد بيانات دائمة ونسخ احتياطية.
2. اربط نطاقًا وشهادات HTTPS بـ WordPress وStrapi. اضبط `PUBLIC_STRAPI_URL` على عنوان Strapi العام، مثل `https://cms.example.com`.
3. غيّر كل أسرار `.env` إلى قيم عشوائية فريدة، ولا تحفظها في المستودع أو صفحة WordPress.
4. أدخل في إعدادات إضافة WordPress عنوان Strapi العام `https://cms.example.com`، وليس عنوان Docker الداخلي.
5. أنشئ رمز Strapi منفصلًا بصلاحية قراءة فقط، وقيّد الوصول إلى لوحة الإدارة وقاعدة البيانات.
6. فعّل النسخ الاحتياطية لقاعدتي البيانات وملفات الموقع، واختبر استعادتها قبل الاعتماد على الموقع.
7. راجع روابط الصور ومصادر المعلومات وإرشادات السفر الرسمية قبل كل تحديث. هذا الموقع تعريفي ولا يؤكد سلامة السفر أو توفر الوصول إلى أي منطقة.

لا تُفتح منافذ قواعد البيانات للعامة. لا ترفع ملف `.env` ولا تستخدم الأسرار التجريبية على خادم عام.

## د. حل المشكلات الشائعة

- **تعذّر فتح لوحة Strapi:** انتظر اكتمال البناء، ثم اقرأ `docker compose logs -f strapi`. تأكد أن المنفذ 1337 غير مستخدم.
- **تعذّر فتح WordPress:** تحقق من `docker compose ps` وأن منفذ 8080 متاح.
- **لا تظهر الوجهات:** تأكد أنها منشورة، وأن الرابط مضبوط على `http://strapi:1337` محليًا، والرمز يسمح بالقراءة.
- **التعديلات لا تظهر فورًا:** اضبط مدة التخزين المؤقت على صفر مؤقتًا أو انتظر انتهاء المدة.
- **الصورة لا تظهر:** افتح رابطها مباشرة في المتصفح، وتحقق من الإنترنت والترخيص. بدّلها بصورة متاحة أو ارفعها إلى مكتبة وسائط Strapi ثم أضف رابطًا عامًا لها.
- **تغيير كلمة مرور قاعدة البيانات بعد بدء المشروع:** أوقف الخدمات وخذ نسخة احتياطية قبل تعديلها؛ قاعدة البيانات المحفوظة تحتفظ ببياناتها. لا تحذف volumes لحل مشكلة كلمة مرور.

لإيقاف الخدمات مع الاحتفاظ بالبيانات: `docker compose down`. لا تستخدم `docker compose down -v` إلا إذا كنت تريد حذف قواعد البيانات وبيانات WordPress بالكامل.
